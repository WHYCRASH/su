# su americanization

## Context
Convert this Android AI-assistant fork into an English-language product named `su`, authored/maintained by `dautist`. Replace the Chinese README with the existing English README, remove China-specific integrations, preserve Gemini functionality, and leave only a Source code button in About linking to `https://github.com/WHYCRASH/su` (confirmed origin remote).

Planning is deliberately surface-level at the user's request. This file will specify execution-stage inventory rather than pretend that all callers have already been audited. No implementation or validation has been performed.

## Grounded findings
- `README_EN.md` is already mostly English but brands the app Daiyu, advertises Breeno/XiaoAI and Kimi Web, and links to upstream releases and communities. `README.md` is Chinese.
- `app/build.gradle.kts` declares namespace/application ID `io.github.mangi.eta`, Java 25, compile SDK 37, minimum Android API 34. Preserve technical identity by default; display renaming does not require a package/data migration.
- `app/src/main/res/values/strings.xml` uses `代鱼` for `app_name` and `agent_accessibility_label`; other service labels still use Eta. Chinese resource variants exist under `values-b+zh+Hans` and `values-b+zh+Hant`.
- Chinese also occurs in Kotlin runtime errors, native comments, built-in skill instructions, docs, and issue templates. Translation must not stop at Android string resources.
- About is `section_about` in `app/src/main/kotlin/io/github/mangi/eta/ui/SettingsScreen.kt`, including updates, communities, source, relay referrals, and donations.
- `ModuleMain.kt` installs both OEM assistant hooks and Google hooks. Xiaomi assistant process also hosts a screen-search hook: wholesale deletion by vendor name could break retained Google functionality.
- `agent/voice/doubao/DoubaoVoiceConfig.kt` currently stores generic voice enablement as well as Doubao configuration. Preserve generic voice state when removing the provider. `SpeechInputSession` has an existing offline recognition branch; shared TTS infrastructure is not Doubao-only.
- China-specific surfaces extend to ColorOS personal-data tools, QQ/WeChat integrations, Ark/Volcengine handling, and built-in Chinese-provider speech choices. Exact complete callers remain unverified; execution must inventory them before deletion.

## Assumptions & contingencies
- Product name is exactly lowercase `su`; fork author is exactly `dautist`; original licensing/copyright and third-party attribution remain intact.
- Preserve application ID, internal English identifiers, protocol IDs, signing configuration, and existing user data. Do not replace every `eta` substring.
- Preserve Gemini, Circle to Search, and shared system/LSPosed infrastructure, including OEM-specific adapters needed to launch Google functionality; remove OEM assistant takeover, not device compatibility simply because the device vendor is Chinese.
- Translation applies to repository-authored prose, including comments/docs, not translation of user content or corruption of external protocol keys, model IDs, vendored notices, or test data that intentionally exercises Unicode.

## Approach

1. **Inventory the full first-party English surface before changing behavior.** Scan tracked source, resources, assets, docs, scripts, issue templates, and build metadata for Han characters and for regional/product markers (`代鱼`, Daiyu, Eta, Breeno, XiaoAI/Xiaobu, Doubao, Volcengine/ByteDance, ColorOS, HyperOS, QQ, WeChat, Chinese provider names, and Kimi Web). Classify each match as user/model-visible prose, repository documentation, implementation identifier/protocol/storage compatibility data, third-party/vendor material, or intentional test fixture. Translate repository-authored prose and user/model-visible labels into English while preserving placeholders, resource keys, JSON fields, wire values, URLs required by retained providers, persisted identifiers, and test semantics. For Chinese locale resource directories, remove the Chinese-only localization surface or replace its values with the same English strings as the default resources so no shipped first-party resource retains Chinese. Do not rewrite third-party license text, vendored source, external provider wire data, or compatibility identifiers merely to make a character scan pass; record these as scan exclusions and verify no user-visible Chinese remains.

2. **Make `su` the product identity without a package/data migration.** Update the default Android app/accessibility labels, assistant/service descriptions, visible assistant role names, runtime-generated UI text, provider client titles, README/docs product references, screenshots/alt text where applicable, and relevant build/metadata display fields from `代鱼`/Daiyu/Eta to lowercase `su` where they describe the product. Keep the namespace/application ID `io.github.mangi.eta`, internal package names, protocol keys, preference/database names, Xposed entry class names, and stored compatibility values unchanged; this is a display-brand cutover, not an installed-app migration. Set the product author attribution in the new README and product-facing About/source presentation to `dautist`; preserve upstream and third-party legal copyright/license attribution rather than falsely replacing legal authorship.

3. **Replace repository documentation with the English product README.** Use the existing `README_EN.md` as the starting content, rewrite it in English as the `su` README, set author/project/release/source links to `dautist` and `https://github.com/WHYCRASH/su` where they describe this fork, remove the Chinese README, and rename/promote the English file to the root `README.md` so the default repository landing page is English. Remove claims and links for deleted Breeno, XiaoAI/Xiaobu, Doubao, Chinese OEM integrations, Chinese communities, Kimi Web, and removed dedicated providers. Retain accurate Gemini, Circle to Search, generic provider/BYOK, offline speech, browser, terminal, and device-tool descriptions. Translate or update first-party docs and issue templates containing Chinese; update/remove links to deleted feature documentation rather than leaving stale promises.

4. **Remove China/OEM assistant and personal-data integrations while retaining Google/Gemini.** In `ModuleMain` and `ModuleConfig`, remove Breeno, XiaoAI, ColorOS memory/direct, and Xiaomi/HyperOS launcher/screen-search package routing, lifecycle package predicates, constants, and dead imports/helpers; delete their dedicated hook implementations and associated handoff/request/image/state code only after execution-stage reference search confirms no retained caller. Remove corresponding `AgentRuntimeWire`/`EntrySurfaceGuard` handoff branches, settings strings, tool catalog entries, capability requirements, personal-data query implementations, protocol/database helpers, package authorities, tests, icons, and docs for ColorOS, QQ, WeChat, Breeno, XiaoAI, and HyperOS. Strip Oplus/ColorDirect/vendor-only branches from shared system files rather than deleting those files when they also implement retained system assistant behavior. Keep `hook/google/GoogleAppHooks.kt`, `GoogleEligibilityHooks.kt`, system-server/SystemUI assistant binding, contextual search/Circle to Search, hotword/Gemini paths, and OEM-neutral voice-assistant entry plumbing. Re-run reference searches after deletion to ensure no feature can still be advertised, routed, or exposed as a model tool.

5. **Remove all dedicated China-provider voice and model integrations, preserving generic speech and Gemini.** Delete the Doubao package and its ASR, duplex realtime, TTS, voice catalog, personal-voice, diagnostics, config, and Volcengine/ByteDance network code; remove `DOUBAO_SPEECH`, `DOUBAO_DUPLEX`, `isDoubaoSpeechHost`, realtime-provider predicates, Doubao catalog IDs, provider-specific settings/navigation, Chinese voice resources, icons, and docs. Update `VoiceModeController`, `VoiceEntryPolicy`, `SpeechInputSession`, `SpeechSynthesisModels`, `SpeechProtocols`, `CloudSpeechSynthesizer`, and UI callers as a clean cutover: retain offline speech and generic `COMPATIBLE_SPEECH`/shared speech-engine paths, remove only Doubao branches, and migrate configuration/state handling so generic/offline enablement is not lost when Doubao preferences disappear. Remove dedicated Kimi Web and Chinese-provider model/catalog/preset integrations and their assets only where they are fork-owned feature code; retain generic OpenAI-compatible/Anthropic/custom endpoints and any provider-independent speech mechanisms. Remove dedicated China-app data features rather than replacing them with another regional service. Do not remove Gemini model support or Google-specific functionality.

6. **Reduce About to one source-code action.** In `SettingsScreen.kt`, replace the entire `section_about` card contents with exactly one source-code button/row. Keep the existing source-code interaction pattern and English source label, change its URL to `https://github.com/WHYCRASH/su`, and remove update checking, Telegram, QQ, relay/referral entries, donation UI/dialog/state/imports/resources/assets, and any other About-only strings. The section may retain its About heading only if the existing screen structure requires it; no other About action or descriptive content may remain.

7. **Finish the cutover and check retained behavior.** After edits, scan first-party shipped/runtime surfaces for remaining user-visible Han text and deleted regional markers, inspect all changed callers/resources for stale references, and confirm the only About action is the source link. Validate that the app identity is `su`, README is English and fork-branded, Gemini/Circle to Search paths remain wired, generic/offline voice paths remain exposed, and deleted China integrations are absent from module routing, settings, tools, assets, and docs. Preserve compatibility identifiers deliberately left in place and document those exclusions in the implementation notes or review output rather than silently changing persisted data.
